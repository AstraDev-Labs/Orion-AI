# Chat model selection and greeting validation

The approved change adds an accessible native model selector beside the Core composer. It lists installed chat models, labels specialist models as tool models, disables changes during a reply, and displays save errors without changing the active selection. A successful selection persists through the settings API and in the local interface preference. Desktop startup respects an installed model from the user's saved configuration before the installer hardware recommendation.

Startup waits for model discovery and server information together; transient failure retries both instead of accepting the first Ollama model. General multimodal chat models remain eligible. Known specialist families are labelled centrally by the server; older servers receive a compatibility classification in the client. A stale request selecting a specialist uses the configured installed chat model, or returns an actionable error if none is available.

Greeting validation applies to streaming and non-streaming requests, including agent-enabled servers. Repeated malformed model drafts produce a visible error after bounded retries, never an unvalidated final draft. Accepted answers are generated by the model.

Verification covers startup ordering, selection persistence, failed saves, actual request model IDs, exhausted retries, specialist fallback, and chat models that also support vision. A browser regression exercises the real interface with controlled API responses. A separate live local-model smoke check exercises the updated server and Ollama. The desktop and installer are rebuilt as release 1.0.2A, retaining the release's alpha warning.
